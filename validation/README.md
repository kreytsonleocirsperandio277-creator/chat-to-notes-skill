# 试用版验证记录

本页记录 v0.1.0 实际做过的检查，范围有限，不代表所有材料都能无遗漏整理。

## 独立实际试用

使用一个不继承原项目聊天的独立 AI，仅提供本技能、所需 supporting references/scripts 及 [14 条虚构聊天](../examples/trial-input.json)。请求是把这些聊天整理成方便继续推进社区影像项目的 Markdown，没有提供标准答案或预期目录。

它实际读取材料、执行两个脚本、生成整理稿与去向表，并回读逐项核对。12 条消息进入主体、1 条进入文末暂存区、1 条无附加信息的“收到。”被排除。主执行 AI 再对照输入检查了结果：展览和访谈位于同一推进分组下；天气、预算、同意范围、设备费用等条件保留；前后更正、第三方转述及旧 AI 反例没有被改成确定结论；未定创意和个人表达保留。

- [实际整理结果](../examples/trial-output.md)
- [独立 AI 的逐项核对记录](independent-check.md)
- [去向表](../examples/trial-coverage.json)

这是实际执行的有限试用，尚不代表真实用户已认可文风，也不证明长材料、多模型、图片附件下的稳定性。单条消息含多个事项时，去向表中的一个定位片段不能证明所有意思都保留，仍须逐点核对。

## 脚本与结构检查

9 项 Python 单元测试通过，覆盖完整 HTML 而非截断预览、多分块、导出清单缺块及数量不符、未知格式、重复 ID、条件保留、缺失去向自动补入、非法去向和覆盖保护。运行命令：

```text
python -m unittest discover -s tests -v
```

另对一份本地真实 QCE HTML 做了只读提取检查：取得 496 条消息，与导出清单一致。原材料未随仓库发布；此项仅验证提取，不声称完成了全量文字与图像的语义核验。

技能通过 skill-creator 的 quick_validate.py 元数据与结构检查。该检查器需要 PyYAML；本技能的两个辅助脚本本身仅用 Python 标准库。

## 尚未覆盖

未实际验证所有 QQ 导出版本、外部消息数据格式、真实图片理解与附件交付、超长材料、其他 AI 产品的技能加载。当前的能力与边界写在 README 和输入方法中；遇到具体问题再用可复现材料改进。
